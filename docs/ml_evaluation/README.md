## Protocol

- **Temporal split, as in `ml/train_points_v3.py`:** train 2020-21, 2021-22, 2022-23, 2023-24; early stopping on 2024-25 (best iteration 96 trees); test 2025-26 and 2026-27. Hyperparameters are `ml.points_model.XGB_PARAMS`, chosen on the validation season. The test seasons were never used to choose anything, including in this evaluation (ablations and seed repeats use the same split).
- **No-leakage design:** one row per player per fixture; player features use only earlier gameweeks (a double gameweek's two fixtures share the pre-deadline values); team strength comes from a separate team-per-match table, also rolled over earlier gameweeks; FPL's historical xP is not a feature (it was recorded inside the gameweek).
- **Metrics:** regression metrics per row (player x fixture). Pick metrics per gameweek after summing a player's double-gameweek fixtures: top-k = mean actual points of the k highest predictions; captain = top-1; hit@20 = share of our top 20 who scored at least the gameweek's 20th-best score; oracle = ranking by actual points. Gameweek values are averaged with equal weight.
- **Baselines on identical rows:** zero (equivalent to a random pick for ranking), training-set position mean, last-3 and last-6 average points, and season-to-date points per game (falling back to last-6, then 0, before a player's first match of the season). Missing histories fall back to 0, so every method is scored on the same 32,973 rows. (The training report drops rows a baseline cannot score, so its baseline numbers differ slightly.)
- **Uncertainty:** 2000 bootstrap resamples of gameweeks, stratified by season, fixed seed 42. Paired differences resample the same gameweeks for both methods.

## Leakage audit

1. **One feature row per input row.** `build_features` returned 166,298 rows for 166,298 input rows (identical); every input row id appears exactly once (0 duplicated ids).
2. **No look-ahead (perturbation test).** 2025-26 GW>=20: 22 outcome columns shuffled (15,572 rows), then rebuilt the features. Rows up to and including that gameweek changed: **0 of 148,300** (0 of 790 at the gameweek itself). Power check: 795 of 795 rows of the following gameweek changed, as they should.
3. **No suspiciously strong single feature.** Highest |Pearson r| with the target on the test seasons: `minutes_r3` 0.536, `season_minutes_share` 0.524, `played_r3` 0.518, `minutes_r6` 0.516, `started_r3` 0.512 (training seasons: `minutes_r3` 0.490). For contrast, FPL's xP correlates 0.69 (2023-24), 0.66 (2024-25), 0.35 (2025-26).
4. **Rank by a single column.** This is the test that exposed the xP leak: a pre-deadline signal should not pick much better than the best honest feature.

v3 is shown only where it is out of sample (2024-25 is the early-stopping season, so mildly optimistic). In the seasons where xP ranks far above every honest feature and above v3, it carries same-gameweek information (team news/lineups), so it cannot be a feature or a fair baseline.

![Single-feature ranking](fig_leakage_single_feature.png)

5. **Validation vs test consistency.** Train (in-sample) MAE 1.020 / top-20 6.50; validation 1.028 / 5.02; test 1.032 / 4.60. Row-level error is nearly the same in and out of sample, so the model is not memorising rows. Pick quality is higher in-sample, as expected for trees that have seen those hauls. The validation top-20 is above the test seasons' even though 2024-25's oracle is lower (10.86 vs 11.22): part of that gap is the mild optimism of early-stopping on that season, part is season-to-season variation. There is no sign of the near-perfect in-sample fit that leakage produces.
6. **Why the legacy v2 numbers (R² 0.72-0.87) were inflated.** Running the old `FeatureEngineer` on 2022-23 turns 26,505 rows into 721,933 (**27.2x**): its opponent-strength merges join per-player values on (season, team, GW). The `shift(-1)` "next match" target then mostly lands on a copy of the same match: for rows scoring 5+ points the target equals the row's own points 97% of the time, against 6% for a player's genuine next match. Together with context features describing the previous match and the leaky xP, that explains the R² far above the 0.55 that even same-match minutes and xG allow.

## Error analysis

- **Availability is the largest error source.** 0-minute rows are 60% of the test set and 25% of total absolute error. Players who averaged 60+ minutes over their last three matches but then didn't play (808 rows, 2.5%) were predicted 2.49 points on average and account for 6% of the absolute error. These are injuries, suspensions and rotation that the historical data can't see; the live pipeline applies FPL's availability flags after the model, which this offline evaluation does not.
- **Hauls (10+ points in a gameweek)** are 608 player-gameweeks (1.9%). 20% were in v3's top 20 and 37% in its top 50 (season pts/game: 15% / 30%); the median haul came from a player ranked in the top 11% of that gameweek. By position: GK 37 hauls (6% of hauls, 2% of v3 top-20 picks, 24% caught in top 50); DEF 194 hauls (32% of hauls, 10% of v3 top-20 picks, 22% caught in top 50); MID 299 hauls (49% of hauls, 62% of v3 top-20 picks, 44% caught in top 50); FWD 78 hauls (13% of hauls, 26% of v3 top-20 picks, 53% caught in top 50).
- **Little history:** 0 (debut) prior matches: n=442, predicted 0.94 vs actual 1.01, MAE 1.13; 1-9 prior matches: n=3,063, predicted 0.91 vs actual 0.92, MAE 0.81; 10-37 prior matches: n=7,848, predicted 0.90 vs actual 0.94, MAE 0.86; 38+ prior matches: n=21,620, predicted 1.27 vs actual 1.31, MAE 1.12.
- **Promoted teams** (2025-26: Burnley, Leeds, Sunderland; 2026-27: Coventry City, Hull City, Ipswich): bias -0.092 vs -0.032 for established teams, MAE 0.870 vs 1.063.
- **Rotation risk** (average minutes over the last three matches): no history: played 37%, predicted 0.94 vs actual 1.01; 0: played 5%, predicted 0.17 vs actual 0.09; 1-30: played 53%, predicted 1.19 vs actual 1.17; 31-60: played 75%, predicted 2.00 vs actual 2.14; 61-90: played 91%, predicted 2.93 vs actual 3.24.

## Limitations and future work

- **No historical availability data.** Injuries, suspensions and rotation news aren't in the training data, so the model predicts an expected value over "plays" and "doesn't play". Adding the FPL status/chance-of-playing history (or a separate minutes model) is the most promising improvement.
- **Player identity is a name string.** In the test seasons 10 (fixture, name) pairs have two rows (Ben Gannon-Doak, Junior Kroupi), and 0 player-gameweeks mix two teams; such players' form features blend two records. A player whose name is spelt differently across seasons also loses his history.
- **Small current-season sample.** 2026-27 has 5 gameweeks, so its intervals are wide and early-season effects dominate it.
- **xG features exist only from 2023-24.** Earlier training seasons have them missing, so the model learns xG-based form from one training season.
- **Irreducible noise.** The oracle top-20 is 11.22 against v3's 4.60, but the oracle uses outcomes; a model told the match's own minutes, starts and xG/xA/xGC still only reaches R² 0.55 (MAE 0.660), and knowing each player-season's true average explains about 0.32 of the per-fixture variance. Goals, assists and bonus are rare and lumpy, so large single-match errors are expected.
- **Single model, squared-error objective.** A Tweedie/zero-inflated objective or a two-stage minutes x points model could fit the zero-inflated target better; ranking objectives (pairwise) could target pick quality directly.

## Production model check

The deployed `ml/models/points_v3.json` (150 trees, refit on 2020-21, 2021-22, 2022-23, 2023-24, 2024-25, 2025-26, 2026-27) scored on the same test rows: MAE 0.946, R² 0.423, Spearman 0.736, captain 9.47, top-20 6.91. **This is optimistic**: the production model was trained on these seasons. It only confirms that the deployed file loads and behaves like the evaluated one; the honest numbers are the ones above.

Cross-check: `ml.points_model.evaluate` on this run's v3 predictions gives top-20 4.595 / MAE 1.032 (combined), versus 4.595 / 1.032 in `ml/models/points_v3_report.json`.
